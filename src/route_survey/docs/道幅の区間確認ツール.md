# 道幅の区間確認ツール

## 役割

手動走行bagの前方映像、路面領域、topURGの水平走査を同じ地点・同じ向きで並べ、
利用者が区間ごとに道幅を判断して記入するための確認資料を作る。

| ツール | 入力 | 出力 |
|---|---|---|
| `tools/measure_cross_sections.py` | waypoints_enu.json、surface_mask.npz | 断面ごとの左右端と曲率のCSV |
| `tools/extract_urg_boundary.py` | bag、最適化姿勢、keyframes.json、hardware.yaml | 鉛直境界の当たり数と走査原点の格子 |
| `tools/extract_route_frames.py` | waypoints_enu.json、bag | 経路距離ごとの前方映像JPEGと`frames.json` |
| `tools/render_width_panels.py` | 上記の出力 | 進行方向上向きの俯瞰図PNG |
| `tools/build_width_review.py` | 映像と俯瞰図 | 記入用の単体HTML |
| `tools/detect_environment_changes.py` | 断面測定のCSV | 環境が切り替わる位置の候補 |
| `tools/summarize_width_stability.py` | 断面測定のCSV、区間のCSV | 区間ごと・左右ごとの検出率とばらつき |
| `tools/estimate_region_widths.py` | 断面測定のCSV、区間のCSV | 区間ごと・左右ごとの横移動量 |
| `tools/apply_region_widths.py` | 区間ごとの横移動量、既存の経路 | 幅2列だけを書き換えた経路CSV |

いずれもROSノードを起動せず、速度指令を出さず、bagと既存の解析結果を読むだけである。
記入結果を走行中の経路へ自動反映する機能はない。

## 断面の取り方

断面の原点は弧長で引いたwaypointとし、向きは前後 `--tangent-span`（既定3 m）の2点から
求めた接線の法線とする。撮影位置から進行方位へ直線外挿すると曲線部で経路を外れるため
使わない。曲率を併記するので、左右の意味が崩れる右左折部を利用者が除外できる。

左右の走査は路面領域の格子をたどり、段差・物体、非路面、未観測のいずれかで打ち切る。
打ち切り理由をCSVに残す。物体による打ち切りは記録日に置かれていた物を含むため、
恒久的な道幅とは区別する。

## 前方映像の取得位置

カメラは車体前方を向いており、車体の真横の断面はほとんど写らない。
このため距離 s の断面を判断する映像には、経路の弧長で `--lead`（既定8 m）だけ手前の
コマを使う。20 m間隔で取り出すと、各コマが断面のおよそ1 m手前から12 m先までを写すため、
経路全体が切れ目なく覆われる。

映像はbagの `/usb_cam/image_raw`（`yuv422_yuy2`、640×480、5 fps）から、waypointの記録時刻に
最も近いコマを選ぶ。選んだコマと要求時刻の差は`frames.json`に残す。

## URGによる鉛直境界

URGは車体の高さ0.49 mを水平に走査するため、路面そのものを観測しない。生垣・壁・柱・
車止め・ロードコーンのような鉛直物だけが写る。走査の配置には地図作成と同じ最適化済み
キーフレーム姿勢を使う。経路のwaypointは別の推定器で記録されており地図と中央0.2 m程度
ずれるため、重畳の基準には使わない。

次の3つを除外しないと、軌跡上に偽の境界が出る。

- `--min-range`（既定0.6 m）: 車体前方0.2 mに車体自身の構造物の反射が常時あるため捨てる。
- `--pose-stride`（既定0.25 m）: 走査の約85%は停止中に記録されている。時間で間引くと
  停止地点の観測だけが積み上がるため、車体が一定距離動くまで次の走査を使わない。
- `--max-range`（既定12 m、8 m程度へ下げる）: 遠距離のビームは車体のピッチで路面に当たる。
  高さ0.49 mでは2度の傾きで14 m先に到達する。

出力の `hits` は格子ごとの当たり数、`origins` は走査原点の数である。当たり数をそのまま
使わず、近傍から見えた走査数で正規化して比較する。物体の種別は判定しない。
高さ方向の情報を持たないため、人や車も同じように写る。
縁石・草地・点字ブロックのような低い境界は観測できない。

## 俯瞰図の読み方

進行方向を上、車体から見た左を図の左に置く。映像と左右が一致する。

| 色 | 意味 |
|---|---|
| 緑 | 路面領域が路面候補とした格子 |
| 橙 | 段差・上方物体の候補 |
| 灰 | 観測はあるが路面候補ではない格子 |
| 白 | 未観測 |

青の三角がカメラ位置、青の線が経路、赤の線が判断対象の断面である。断面上の緑と青の
太線が左右の端までの距離を示す。格子は20 cmで、色のない場所を走行不可と断定したもの
ではない。

## コーンの扱い

つくばチャレンジのコースは緑のロードコーンで区切られる区間があるが、同じ種類のコーンが
障害物としても置かれる。並び方でしか区別できないため、俯瞰図にコーンの印は描かない。
利用者が映像で、経路に沿って並ぶ境界のコーンか、単独または群で置かれた障害物かを判断する。

障害物として置かれている区間では、幅を絞ると回避できずに停止する。幅を狭める方向へ
扱わない。記録したコーンと随伴者は記録日の配置であり、走行当日の配置ではない。

## 実行

```bash
source /opt/ros/jazzy/setup.bash

python3 src/route_survey/tools/measure_cross_sections.py \
  --waypoints <経路>/waypoints_enu.json --surface-mask <路面場>/surface_mask.npz \
  --output <出力>/cross_sections_1m.csv --spacing 1.0

python3 src/route_survey/tools/extract_urg_boundary.py \
  --poses <地図>/optimized_poses_enu.npy --keyframes <グラフ>/keyframes.json \
  --hardware <地図>/hardware.yaml --surface-mask <路面場>/surface_mask.npz \
  --run-cache <記録区間キャッシュ> --bag-root <bag置き場> \
  --waypoints <経路>/waypoints_enu.json --output <出力>/urg_boundary.npz \
  --scan-stride 2 --max-gap 6.0 --pose-stride 0.25 --max-range 8.0 --min-range 0.6

python3 src/route_survey/tools/extract_route_frames.py \
  --waypoints <経路>/waypoints_enu.json \
  --run-cache <記録区間キャッシュ> --bag-root <bag置き場> \
  --output <出力>/frames --spacing 20 --lead 8

python3 src/route_survey/tools/render_width_panels.py \
  --frames <出力>/frames --surface-mask <路面場>/surface_mask.npz \
  --cross-sections <出力>/cross_sections_1m.csv \
  --waypoints <経路>/waypoints_enu.json --output <出力>/panels

python3 src/route_survey/tools/build_width_review.py \
  --frames <出力>/frames --panels <出力>/panels \
  --review-widths <幅推定>/review_widths.csv --output <出力>/width_review.html
```

`--bag-root` は複数指定できる。記録区間ごとにbagの置き場が分かれている場合に使う。
bagが見つからない記録区間は、その旨を表示して対象から外す。
出力は生成物であり、リポジトリの管理対象には追加しない。

## 区間の決め方と、左右の値の決め方

走行環境は数十mから百m超にわたり同じ性質が続く。`detect_environment_changes.py` は
境界までの距離と検出率が前後で大きく変わる位置を候補として挙げる。候補を挙げるだけで
区間を確定しないため、利用者が映像で確認して確定する。窓の長さと最小間隔を広げると
候補が減る。出入口や個々のコーンを拾わない程度に広げる。

確定した区間に対し `summarize_width_stability.py` を実行し、左右それぞれについて
検出率とばらつきを見る。左右の和（道幅）は、片側に境界が無い区間では意味を持たない
ため判定に使わない。

| 検出率 | ばらつき | 意味 | 扱い |
|---|---|---|---|
| 高い | 小さい | 連続した境界がある | 中央値から余裕を引いて採用する |
| 低い | — | 境界が探索範囲の外にある | 広い場所として扱う |
| 高い | 大きい | 出入口などで境界が不連続 | 映像で判断する |

## 境界の種類と測り方

境界の種類は利用者が映像で判断し、区間表の `left_type` / `right_type` に与える。
種類ごとに測り方が異なる。

| 種類 | 測り方 | 根拠 |
|---|---|---|
| `continuous` | 近い側の検出に1次式を当てはめ、その値から車体半幅と余裕を引く | 生垣・壁・フェンスは連続している |
| `cone` | 同じ当てはめに追加の余裕を引く | ロードコーンの設置は直線から外れ、外側はコース外である |
| `discrete` | 区間内の下側5%点を使う | 柱や車止めは間を通れるが、最も近いものに合わせる |
| `none` | 上限値を使う | 探索範囲に境界が無い |
| `open_wide` | 広い区間の上限値を使う | 障害物が多く、回避余地を確保する必要がある |

ロードコーンが路端を成す区間では、コーンの隙間から遠くの物が見えるため、断面ごとの
検出距離の分布が二峰になる。近い峰だけを残さないと代表値が隙間の値に引かれる。
近い側として残す上限は既定 1.8 m で、広場にコーンを疎に置いて通路を示す区間では
区間表の `near_limit_m` 列で広げる。

コーンが路端を成すのはコース上の限られた区間であり、どこかは映像で判断する。
つくば市役所一帯の敷地内に境界のコーンは無く、敷地内のコーンは障害物である。

## 経路への反映

`apply_region_widths.py` は既存の経路CSVの `right_is_open` と `left_is_open` だけを
書き換える。座標・方位・停止属性・ラベルは変更せず、入力のCSVも上書きしない。
区間の境界では値が不連続に変わるため、`--blend` で前後に遷移をかける。遷移中の値は
両端の大きい方を超えない。

反映後は、幅2列以外の列が入力と一致することを確認する。

## 記入のしかた

HTMLをブラウザで開く。区間ごとに種別（歩道・広い／狭い・並ぶ／車道隣接／判断保留）を
選び、左右の幅を記入する。`j`・`k`で区間を移動、`1`〜`4`で種別、`c`で前区間の値を複製する。
入力はブラウザに自動保存し、CSVとJSONで取り出せる。JSONを読み込めば途中から再開できる。

CSVの`left_m`・`right_m`が利用者の判断値、`left_estimate_m`・`right_estimate_m`が
路面領域から求めた参考値である。本番の経路CSVへ反映する手順は別に決める。
