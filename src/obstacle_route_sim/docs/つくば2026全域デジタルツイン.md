# つくばチャレンジ 2026 全域デジタルツイン生成・レビュー

## 1. 対象と到達点

2026-09-13 時点の公式必須コース全域を含む約 809 × 434 m の地理モデルを生成した。
公式図を目視トレースした概略中心線は 2,223.95 m、1,142 点である。
市役所周辺から研究学園駅・ホテル外周を含む。選択課題の達成判定は対象外とする。
現地測量で校正したデジタルツインではなく、公開地理情報と航空写真による初期モデルである。
黄色線は概略経路であり、全区間を実際に走行した軌跡ではない。

提供版 terrain3d v0.4.1 は変更せず、core / geo / recon / world と exporter を再利用した。
添付内の記載は資料として扱う。生成した同一メッシュをブラウザと Gazebo で使用する。

## 2. 資料・位置合わせ・精度

| 入力 | 用途・出典 | 制限 |
| --- | --- | --- |
| 公式 2026 コース図 | [公式課題](https://tsukubachallenge.jp/2026/regulations/tasks)、[コース図](https://tsukubachallenge.jp/2026/wp-content/uploads/course_2026.jpg) | 図上トレース。停止位置や通行帯の測量値ではない |
| Esri World Imagery | [サービス情報](https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer?f=pjson)、z19 写真 | 当該範囲の提供元メタデータは撮影日 2024-01-10、元解像度 0.46 m、位置精度欄 5 m |
| 国土地理院 | [写真・標高タイル](https://maps.gsi.go.jp/development/ichiran.html) | 写真は位置合わせ、DEM は地表高。2 m 出力格子は測量精度を意味しない |
| OpenStreetMap | [地図](https://www.openstreetmap.org/#map=17/36.08375/140.07950) | 建物輪郭・高さタグ・道路・樹木・駐車場等。欠落や更新差がある |

Esri の当該範囲メタデータは `source/esri_extent_metadata.json` に保存する。
Vivid Advanced / GE01 / Vantor、BlockName は Vivid_Advanced_Tokyo_JP_24Q2 である。
画像タイルの細かさを実際の解像度・位置精度と混同しない。2026 年の現況写真ではない。
出典表記は Esri, Vantor, Earthstar Geographics, GIS User Community、
© OpenStreetMap contributors（ODbL）、国土地理院、つくばチャレンジ 2026 とする。
取得 URL とハッシュを source の manifest / provenance に残す。

公式図と国土地理院写真の対応点 5 点を初期値とし、近傍に限定した SIFT と affine RANSAC
で位置合わせした。25 inliers、RMSE 1.101 px（当該画像上で約 0.53 m）である。
これは画像間の当てはまりであり、現地に対する絶対位置精度ではない。
繰り返し模様で誤対応した大域 SIFT の結果は採用していない。

水平座標は提供版の球近似ローカル平面である。厳密な測量座標系への校正は未実施。
DEM は中心標高を差し引く。GNSS 楕円体高原点 67.078 m は既存設定由来の仮定であり未校正。

## 3. 再構成した特徴物

| 種別 | 数 | 再構成方法 |
| --- | ---: | --- |
| 建物形状 | 161 | OSM の建物・building part、高さタグまたは既定値。棟数とは異なる |
| 樹木 | 213 | OSM と航空写真の樹冠候補を統合。幹と樹冠を簡略形状にする |
| 駐車車両候補 | 239 | OSM 駐車場内の明るい矩形を寸法・縦横比で抽出。高さ 1.5 m を仮定 |
| 植栽帯候補 | 108 | 緑色領域の細長い形状を抽出。高さ 0.8 m を仮定 |
| 道路／barrier | 215 / 4 | OSM 地理形状を取り込む |
| OSM point | 201 | 樹木・横断等を含む入力件数。すべてが障害物ではない |

提供版の樹冠検出は 4,719 候補を出したため、色・道路・駐車場・建物除外マスクで
141 候補に絞り、OSM 樹木と統合した。影、屋根、冬季落葉による誤検出・見落としは残る。
車両は撮影時点の静止候補で、暗色車は検出しにくい。高さは単眼写真から実測していない。
建物の窓・軒・通路下面、縁石、標識、細いポール、信号灯器などの現地細部は未再現または不完全。
LiDAR で見える幾何特徴の近似であり、材質別反射強度や Mid-360 非反復走査は再現しない。

## 4. 生成物と表示

生成先は `log/codex/tc2026_full/` とし、Git に追加しない。
クローン後の再現確認には、写真を除いて固定した
[同梱版 maps/tsukuba2026](../maps/tsukuba2026/README.md)を使用する。
この固定版はGitで追跡し、地図の再取得・再生成を必要としない。
`environment.sdf` は環境、`trial.sdf` は i-Cart mini を含む試験 world である。
`world.json`、598 個の参照メッシュ（地形を含む）、地表写真テクスチャを出力する。
`scene.json` は提供版の編集用 scene、`route.csv` は概略中心線、
`reconstruction.geojson` は経路と検出候補の地理情報である。

`index.html` は高さ倍率 1× の全域 3D 表示、上空・市役所・駅周辺への視点切替、
建物・樹木・車両・植栽・経路・不整合候補の表示切替、航空写真比較を提供する。
`editor.html` は提供版に scene を埋め込む。`overview.png/pdf` は静的概要図である。
ブラウザ用資産は生成物の viewer_vendor に配置する。
新規処理はパッケージ固有の補助機能なので tools、設定は params、検証記録は docs に置く。

## 5. 確認結果

全 world の SDF 検証は Valid。Gazebo に読み込み、隔離 DDS domain 86 と専用 partition
で 25 秒の起動・走行・センサ配信試験を行った。

| 確認項目 | 結果 |
| --- | --- |
| GNSS 由来自己位置 | 210 messages |
| LaserScan / PointCloud2 | 405 / 203 messages |
| 真値 pose / odom / cmd | 779 / 780 / 423 messages |
| GNSS 自己位置と直近真値の XY RMSE | 0.0838 m。仮定した誤差・遅延を含む試験内値 |
| 最大 odom 速度 | 約 0.9 m/s |
| 車体接触通知 | 0。全ルート無接触を意味しない |
| 完走判定 | false。25 秒で試験打切り、全 2.224 km は未走行 |
| 終了処理 | 子プロセス回収成功 |

GNSS master は車軸上 z=0.7 m、slave は後方 0.5 m、Top-URG z=0.3 m、Mid-360 z=0.6 m
を使用する。未提示の取付位置・質量・重心・駆動応答は仮定を含む。
模擬 NavSatFix 等から実際の geo_pose_converter を経由する。
この試験は GNSS dropout を発生させていないため、result の dropout_stop_pass=false
は当該機能の失敗判定として使わない。過去の途絶試験は別の検証記録を参照する。

半径 0.20 m の平面投影による経路重なり監査では、1,142 点中 63 点・5 物体に不整合候補がある。
対象は photo_hedge_76、photo_hedge_77、osm-way-252454244、643207737、706453816。
上下の通過余裕を評価しない粗い幾何検査であり、現地の通行不能を意味しない。
写真と地図のずれ、植栽の誤検出、建物の通り抜け構造を確認する必要がある。
公式線を都合よく移動して通過成功にせず、geometry_audit.json と画面に保持する。

pytest は関連テスト合計 47 passed。地理変換、非有限入力、駐車場マスク、樹木除外を追加確認した。
obstacle_route_sim の通常 install と --symlink-install は双方成功した。
既存詳細設計書 10.4、地理地図 GNSS 検証記録、README を参照し、詳細設計書 10.5 と改版履歴、
README に本資料への入口を追加した。コードの出力 schema と生成 JSON、ブラウザ表示を照合した。

## 6. 再生成手順

ROS Jazzy、既存シミュレータ依存、Python requirements を準備する。
Gazebo 未導入環境のローカル runtime は既存の検証資料を参照する。
ワークスペースルートで実行する。

```bash
npm install --prefix log/codex/digital_twin/node_runtime --ignore-scripts --no-audit --no-fund three@0.128.0
export NODE_PATH="$PWD/log/codex/digital_twin/node_runtime/node_modules"
python3 src/obstacle_route_sim/tools/prepare_full_course.py --output log/codex/tc2026_full --config src/obstacle_route_sim/params/tc2026_reconstruction.json
python3 src/obstacle_route_sim/tools/reconstruct_full_course.py --output log/codex/tc2026_full --config src/obstacle_route_sim/params/tc2026_reconstruction.json
python3 src/obstacle_route_sim/tools/audit_full_course.py --output log/codex/tc2026_full
python3 src/obstacle_route_sim/tools/preview_full_course.py --output log/codex/tc2026_full --three-directory log/codex/digital_twin/node_runtime/node_modules/three
python3 -m http.server 8768 --bind 127.0.0.1 --directory log/codex/tc2026_full
```

取得済み source キャッシュを再使用する。新規取得時は提供元の更新で結果が変わり得る。
ブラウザで localhost:8768 を開く。route.csv の停止フラグは未設定で、実機へ投入しない。

## 7. 完走評価に向けた残項目

優先順位は、5 箇所の不整合の現地照合、歩道と通過可能空間・縁石・段差・停止位置の測量、
車体とセンサ外部パラメータの校正、校正後の全ルート連続走行である。
全コースモデルを作成したことと、必須課題完走を確認したことは区別する。
大会当日のコーン・歩行者・駐車車両、GNSS multipath と遮蔽、SLAM と再局在、
交通条件、雨、電池、実機制動はこの全域試験では未検証である。

## 9. 俯瞰・各区間の静止画像

`tools/render_full_course_views.py` は同一物体メッシュと地形から全域、市役所、
接続道路、北側沿道、駅前の PNG を生成する。表示用の樹冠のみ多面体に簡略化する。
物体色は種別表示、黄色線は概略経路である。遮蔽を避けるため経路は前面に表示する。
境界に跨る物体は全体を残すため、切り出した地面の外に形状が延びる場合がある。

```bash
python3 src/obstacle_route_sim/tools/render_full_course_views.py --source log/codex/tc2026_full --output log/codex/tc2026_full/views
```

5 枚を生成して目視確認した。描画専用追加のため ROS 再走行・pytest の追加は行わない。
通常 install と symlink install の両方を確認する。

## 10. 左右 1 m の通路確保版

ユーザー指定により `tools/clear_route_corridor.py` で別の試験用モデルを生成する。
元の全域モデルは保持し、調整版は `log/codex/tc2026_corridor_1m/` に置く。
地面とロボットを除く物体は、経路の全線分から 1.01 m 以上離す。
メッシュの平面凸包と樹冠の外接円を使う保守的判定で、上空形状も対象に含む。
0.1 m 刻み・5 度刻みで 2 m 以内の移動を探索し、解消できなければ削除する。
これは現地測量に基づく補正ではなく、走行試験用の人為的変更である。
移動先と他物体との重なり、全区間の走行成功は未検証である。

11 物体を移動、9 物体を削除した。内訳と変位は `corridor_changes.json` に保存する。
建物 1 形状を 2 m 移動、建物 2 形状を削除し、残りは植栽・樹木である。
独立した SDF collision の読み直しでも 801 形状の最小離隔は 1.0113798068 m、
1 m 未満の干渉は 0 件であった。これは平面幾何条件の確認である。
元の経路 CSV は変更しない。元の航空写真は変更しないため、写真上の物体は残る。
調整対象は OBJ、SDF、world JSON、viewer_data のモデルである。
提供版 scene は元の再構成データなので調整版に同梱せず、編集リンクは変更記録へ置き換える。

```bash
python3 src/obstacle_route_sim/tools/clear_route_corridor.py --source log/codex/tc2026_full --output log/codex/tc2026_corridor_1m
```

Shapely 2.x を使用する。全線分間の干渉、移動上限、削除、非干渉物体保持のテストは
`tests/test_route_corridor.py` の 3 件が成功した。通常と symlink の両ビルドを確認する。
今回は幾何調整であり ROS / Gazebo 再走行は実施していない。
