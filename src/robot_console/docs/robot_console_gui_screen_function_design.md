# robot_console 画面・機能詳細設計書

## 画面構成

MainWindowはPyQt5の7タブで構成する。ScaledCanvasで画面全体を拡縮する。
通常の運行監視と操作はダッシュボードに集約し、詳細情報は対応タブで確認する。
実機の時刻同期警告は全タブの上部に表示する。

| タブ | 表示・操作 |
| --- | --- |
| ダッシュボード | 運行フェーズ、Route/Follower、Drive/CmdVel、GPS/Pose、イベント、Node Health、Manual Ops、起動操作、bag保存 |
| 自己位置・センサ情報 | 経路・自己位置・目標の地図、センサ画像、カメラ認識表示 |
| 起動・設定 | 環境・運転モード、プリセット、候補／起動予定、config・引数編集、記録ルート選択 |
| コンソールログ | profileごとのプロセス状態・stdout/stderr・保存ログ |
| GNSS・基地局 | GNSS品質、アンテナ方位・基線長、局情報、RTCM通信状態 |
| ルート記録 | ICP／GNSS融合の採取状態、開始／終了、点数、左右幅候補・理由、保存中／完了／エラー |
| 地図作成 | bag選択、FIX・ICPグラフ生成、進捗・中止・結果再表示、俯瞰確認、次回ICP走行・ルート記録への地図設定 |

## 実機の操作フロー

1. 起動・設定で「実機／手動走行」を選び、プリセットを適用する。
2. 場所・RTK局・保存先とICP地図を確認し、重複する起動構成を停止する。既定地図はつくばのFIX拘束地図。
3. ダッシュボードで一斉起動し、ICPの初期化と自己位置の受信を待つ。初期値は良好FIX＋方位または手動設定を使う。
4. ルート記録で開始し、L1を保持して操縦する。停止属性はコントローラから記録する。
5. 車体を停止して終了・保存を行い、保存完了を確認する。
6. 採取構成を停止し、「実機（ICP）／自律走行」またはGNSS系の「実機／自律走行」で保存ルートを選ぶ。
7. 経路・原点・設定・幅未確認点を確認して起動し、始点付近でmanual_startを送る。

「実機（融合）／手動走行」または自己位置設定 `gnss` でGNSS融合による記録を選べる。
ICP照合不良中はLIO予測を要確認として記録し、自動幅を0にする。LIO途絶時は新しい点を追加しない。
保存は別ワーカーで行い、終了時の書込み成功まで保存完了と表示しない。エラー時は終了・保存で再試行する。
記録開始／終了は速度指令を出さない。終了は位置途絶中も可能で、保存失敗は完了と表示しない。
採取状態が3秒届かなければ未接続に戻し、操作を無効にする。
採取中・2点未満・必要ファイル欠落の経路は自律起動に使わない。

## ダッシュボードの入力

Manual Opsからmanual_start、sig_recog、road_blocked、固定障害物ヒント、静止画像入力を送れる。
manual_start=trueは開始・停止点からの再開、falseは入力解除であり走行停止ではない。
実際の手動介入はdrive_mode_managerのL1＋PSを使う。
固定障害物ヒントは停止操作で解除し、通常のobstacle_monitorへ戻す。

## ROSBAG保存

ダッシュボードの「ROSBAG保存」で保存先を選び、記録開始を押す。終了時は停止・保存を押し、
保存完了になるまで待つ。記録状態、経過時間、保存容量、保存先と出力フォルダ名を表示する。
空き容量は状態欄、出力先の完全なパスはフォルダ名のツールチップで確認できる。
HTML遠隔観測UIには操作・状態表示を置かない。

既定の保存先はPCの `~/rosbags`。環境変数 `ROBOT_CONSOLE_BAG_DIR` で初期値を変更でき、
UIの保存先欄または「変更…」でも変更できる。記録中は保存先変更・二重開始を無効にする。
同じ保存先を使用する別UIとの同時記録もロックで防ぐ。
日時とランダムIDのフォルダを毎回作り、既存bagを上書きしない。

`ros2 run robot_console record_bag_with_map` を起動する。内部のrosbagは
`--all-topics --storage sqlite3 --max-bag-size 1073741824` を使い、除外正規表現
`^/(Laser_map|sensor_viewer)$` で記録用relayに置き換える元トピックを除外する。
通常トピックは開始後に出現するものも探索する。

| 元トピック | bagへ記録するトピック | 記録周期 |
| --- | --- | --- |
| `/Laser_map` | `/Laser_map_record` | 10秒 |
| `/sensor_viewer` | `/sensor_viewer_record` | 1秒 |

各周期に受信済みの最新1件を記録し、元の時刻・frame_id・点群／画像データを保持する。
Sensor Viewerは非圧縮画像のまま頻度だけを下げる。カメラ画像はこの間引きの対象外。
GUIは元の `/sensor_viewer` を購読し、通常の配信頻度で表示する。
地図の表示更新・蓄積密度、障害物判定と走行用ヒントも通常どおり動作する。
新しい入力がない周期は古いデータを再配信しない。最初の記録用地図は開始約10秒後、
記録用Sensor Viewerは約1秒後のため、それより短い記録には含まれない場合がある。
relayは記録開始時に起動し、停止時に終了する。
再生側で元トピック名が必要なら次を使う。

```bash
ros2 bag play <bag> --remap /Laser_map_record:=/Laser_map /sensor_viewer_record:=/sensor_viewer
```

隠しトピックとサービスは対象外。ROS_DOMAIN_ID等はUIの実行環境を引き継ぐ。
センサ・点群・画像を含むため、実機で必要な受信レートと保存媒体の速度を確認する。
bagは約1 GiBごとのdb3ファイルとmetadata.yamlで構成される。親フォルダに同名.logも残す。

停止はSIGINTを送り、プロセス正常終了とmetadata.yamlの存在を確認して保存完了とする。
UIの通常終了・SIGINT/SIGTERM終了時にも停止処理を行う。
20秒以上終了しない場合はSIGTERMを送り、正常保存とは扱わない。
強制電源断・SIGKILLでは最終保存を保証できない。
開始時に空き1 GiB未満なら開始せず、記録中512 MiB未満になったら停止する。
停止・エラーで保存済みファイルを自動削除しない。

実装は `core/bag_recorder.py`、Qt表示は `ui_qt/widgets/bag_card.py` に配置する。

## 地図とセンサ

地図はactive_routeのLLHを表示する。未走行は緑、走行済みは灰、現在位置は水色、目標は黄色。
初回受信・形状変更で全体表示し、進捗更新では手動の拡大率を維持する。
「ルート全体」で表示範囲を戻せる。最大zoomは22、19超は背景タイルを拡大表示する。
GNSS単独方位は北基準時計回り、融合yawはmap基準反時計回りと明示する。

Qt側は `QWebEngineView` に地図HTMLを埋め込み、HTML遠隔観測UIと同じ Leaflet 1.9.4 と
OSMタイルで描画する。同じ実装を共有することで両UIの表示内容を揃える。waypoint列は
緯度経度を持つものだけを描き、現在indexを境に走行済みと未走行を色分けする。

画像列は上からフロントカメラ、Sensor Viewerの順に縦積みとし、QtとHTMLで順序を揃える。
実機カメラはusb_camの `/usb_cam/image_raw`。道路封鎖・信号の認識ノードは画像を配信せず、
`/perception/*/overlay` の検出矩形・判定をConsoleCoreが同じカメラへ重畳する。
採用検出は太線、採用外は細線・灰色、フレームとの時刻差が大きい枠は破線とする。
直近の認識枠は保持期限内で後続フレームにも描画する。
GO/STOP・封鎖状態とstatus_noteは画像直下の判定チップに表示し、未受信でも枠を残す。
Qtの地図と画像列の横比は3:2、画像列内のカメラとSensor Viewerの行高比も3:2。
HTMLはカード幅に上限を設けて中央に置く。
画像表示の有無だけで認識結果やセンサ較正の有効性を判断しない。

## GNSS・基地局

ダッシュボードに基地局/RTCM状態とマウントポイントを表示する。
「GNSS・基地局」タブに地域、局名、ホスト:ポート、マウントポイント、CRC確認済みRTCMの
受信速度・累積量・最終受信からの秒数、再接続回数、通信エラー種別を表示する。
GNSS欄はRTK状態、衛星数、HDOP、補正データ年齢、方位・標準偏差、アンテナ間距離、
主アンテナの緯度・経度・高度。方位はアンテナ間の北基準時計回りであり、融合車体yawとは区別する。
標準偏差は推定品質であって実測誤差ではない。

診断 (`std_msgs/String` JSON) を1 Hzで購読する。GNSSは実機・模擬とも
`/rtk_gps/rtk_status` と `/rtk_gps/ntrip_status` に配信する。
単独起動・GUIの一斉起動・共通起動・HTML観測UIは同じ公開名を使用する。
明示的に別の配信元を使う場合はQt launchの `rtk_status_topic` / `ntrip_status_topic`、
HTMLの `--ros-args -r` で指定する。起動コマンドは[README](../README.md)を参照する。

GNSS位置コールバックとは独立して診断を送る。接続成功と補正受信を区別し、CRC有効RTCMが
5秒以上届かないと補正途絶。UIが診断topicを2.5秒超受信しないと更新遅延、5秒超で情報途絶。
GNSS自体の鮮度は既存の1秒/3秒閾値。未受信の数値は「—」、古いFIX表示を正常色にしない。
NTRIPを使わない設定は「無効」。外部補正入力の有無をNTRIP無効から推定しない。
シミュレーションはNTRIPを持たず、`DISABLED` を配信する。無配信による診断途絶とは区別する。
認証ユーザー・パスワード・サーバ応答本文は診断JSONに含めない。

局名・地域は単独起動と `prepare_real_session` が同じ基地局カタログから
`ntrip.station_id/station_label/site` に設定する。
「起動・設定」で「RTK GPS UM982」または「実機・手動走行／軌跡取得」を選び、
場所とRTK補正局を指定する。地域の既定局・地域内の個別局・NTRIPなし・独自局を選べる。
場所変更時は別地域の局を地域の既定局へ戻す。
独自局は認証情報を含む接続設定YAMLを「独自局の設定ファイル」で指定する。
編集は起動中の接続を変更しない。切替時は現在のGNSSまたは共通構成を停止し、再起動する。
本タブは観測画面であり、走行中の接続先変更機能は設けていない。

HTML遠隔観測UIは測位状態・衛星数・基地局受信状態の3項目のみ常時表示する。
詳細は標準details要素にまとめて初期状態で閉じる。開閉状態は定期更新でも維持し、
ページ再読み込み時は閉じる。スマートフォン幅で接続先を折り返す。

## 警告と表示上の制約

R1によるGNSS途絶模擬は赤、通知期限切れは黄で表示する。
実機時刻同期は未成立・喪失を全タブで警告し、復旧後は共通構成を再起動する。
GNSS/NTRIPの未受信・期限切れの数値は正常色で表示しない。

画面モデルに存在しても、以下の値は運用判断の根拠にしない。

- signal_stop_active／line_stop_activeは停止属性からの導出が未実装で、既定値のままである。
- within_arrival_thresholdは到達閾値を受信して算出する機能がない。
- Node Healthのlast_log_levelとrequired_but_not_selectedは実際の警告判定を網羅しない。

停止理由は経路属性・follower状態・ログを併せて確認する。
プロセスのRUN数は起動グループ数であり、すべてのセンサが正常なことを表さない。

## HTML遠隔観測と確認方法

HTMLはSnapshotによる読取専用表示で、走行・起動停止・bag・採取操作は提供しない。
GNSS詳細は折りたたみ、スマートフォン幅でも接続先を折り返す。
HTTPサーバはloopbackで待ち受け、認証機能を持たない。
別端末への公開範囲と手順は[README](../README.md)に従う。
PC内URLは遠隔端末から直接開ける共有URLではない。

表示元の構造は[アーキテクチャ](robot_console_gui_architecture_design.md)、
操作手順は[README](../README.md)を参照する。

`tools/tests/` と `tools/check_qt_entry.py` でSnapshot・各画面・実ROS受信を確認する。
GNSS・基地局は不正JSON、未受信、期限切れ、機密フィールド除外、Qt/HTML表示を確認する。
ROSBAG保存は二重開始、別UIとの競合、空き容量不足、起動失敗、停止・保存状態を確認する。
ネットワークとデバイスを隔離したROS結合試験では、地図の10秒周期、Sensor Viewerの1秒周期、
画像データと元時刻の保持、元画像の高頻度配信、入力停止後の重複抑止を確認する。
記録後はmetadata.yamlと必要トピックのメッセージを確認する。

模擬NTRIP診断の表示と、実GNSSの測位品質・補正受信は区別する。
実機センサ一式の帯域・保存媒体性能・長時間保存は実構成で検証する。
画面表示試験は実機運動の検証を代替しない。
