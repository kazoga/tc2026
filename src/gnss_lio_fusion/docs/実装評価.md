# GNSS/LIO 融合 第1段階 実装評価

## 1. 実装と試験条件

2026-09-13に適応baseline、GNSS/LIO平面EKF、時刻内挿、速度制限を実装した。
[詳細設計書](詳細設計書.md)を仕様とし、obstacle_route_simの既存評価ツールへ--fusionを追加した。
FAST-LIO本体、厳しめLiDAR/IMU係数、既存地形原本は変更していない。
conservative・seed=1を使用し、建物近傍でFLOAT、位置bias最大各軸1.2 m、
位置雑音σ0.6 m、方位σ5度の既存仮定を併用した。
baseline観測σはFIX時2 mm、FLOAT時40 mmとした。実機の測定分布ではない。

走行は融合ENU poseで操舵し、URGと既存障害物回避を有効にした。
融合ノードは真値・建物配置を購読しない。真値はGPS観測生成と評価器だけが使う。
単独GPS/LIOの精度は、同じ融合走行のセンサ観測を比較した値である。
GPS単独・LIO単独の操舵で同じ結果になることを意味しない。

## 2. 短区間の閉ループ結果

生成物はlog/codex/fusion_trial/fixedとtransitionに保存した。

| 指標 | FIX中心・22 waypoint | FIX→FLOAT→FIX・70 waypoint |
| --- | ---: | ---: |
| goal_pass | true | true |
| 真値ゴール誤差 | 0.167 m | 0.331 m |
| GPS観測XY RMSE | 0.023 m | 1.025 m |
| LIO初回整合XY RMSE | 1.202 m | 13.409 m |
| 融合XY RMSE | 0.470 m | 0.859 m |
| 融合最大XY誤差 | 1.642 m | 1.932 m |
| 車体中心の最大経路横ずれ | 0.148 m | 1.342 m |
| 車体中心が経路±1 m以内の比率 | 100% | 89.04% |
| 車体等の監視対象への接触イベント | 0 | 0 |

GPS/LIO/融合は共通時刻0.2秒間隔で比較した。0.5秒超の入力間隔にまたがる補間を除外した。
FIX試験は共通283標本・除外6標本、遷移試験は共通1,053標本・除外6標本である。
両試験のLIO最大入力間隔は0.6秒だった。サンプルは独立試行ではない。

FIX試験では初期の実際のbaselineを515 mmにし、推定値515.16 mmを取得した。
遷移試験では開始25秒後に500→520 mmへ変更し、1回の再取得を経て519.76 mmとなった。
FLOAT中の距離変動に基準値が引きずられず、FIX復帰後に通常更新を再開した。
遷移試験の診断はGPS_LIO 942標本、LIO_PRIORITY 535標本であった。

融合はLIO単独より改善したが、良好GPS単独より悪い場面がある。
遷移区間も完走したものの、±1 mを外れたためコース内走行として合格とはしない。
FIX/FLOAT・衛星数・baselineだけでは、LIOの緩やかな誤推定やGPSの共通biasを完全に識別できない。

## 3. 保存済み全周記録の再生

log/codex/fastlio_full_conservative_seed1の約42.89分のLIO記録に、建物近傍GPSを新しく生成した。
結果はlog/codex/fusion_trial/full_replayに保存した。

| 指標 | GPS | LIO | 融合 |
| --- | ---: | ---: | ---: |
| XY RMSE | 1.127 m | 35.396 m | 2.319 m |
| XY誤差P95 | 2.393 m | 55.186 m | 4.443 m |
| 最大XY誤差 | 4.252 m | 59.269 m | 13.404 m |

融合の誤差増加は長いFLOAT区間で顕著だった。LIO優先だけでは、GPS単独より悪くなる場合がある。
GPSが信用できない期間も弱い位置観測を使うが、LIO自体の誤差を抑え切れない条件が残る。
これは走行軌跡を固定した観測時刻順のコア再生であり、融合制御の全周完走ではない。
GPSは再生成した仮定観測で、元の同時記録GPSではない。
通信遅延・DDS欠落・閉ループの変化・真値roll/pitchによるアンテナ補正は再生の対象外とする。

## 4. 実行・再現手順

ROS Jazzyとビルド済みoverlay、Gazebo runtimeを有効化して実行する。
出力先は毎回新しいディレクトリを使用し、過去の失敗結果も保持する。

```bash
python3 src/obstacle_route_sim/tools/prepare_fastlio_trial.py --source <IMU追加前の試験world> --output <試験出力先>
python3 src/obstacle_route_sim/tools/evaluate_terrain_trial.py --world <試験出力先> --gnss --fusion --building-gnss --fastlio <FAST-LIO実行ファイル> --lio-noise-profile conservative --lio-noise-seed 1 --baseline-shift 0.02 --baseline-shift-after 25 --timeout 600
python3 src/obstacle_route_sim/tools/review_fusion_trial.py <試験出力先>
python3 src/obstacle_route_sim/tools/evaluate_fusion_replay.py --source log/codex/fastlio_full_conservative_seed1 --output <新規再生出力先>
```

短区間のFIX試験では--building-gnssを外し、baseline-shift=0.015、shift-after=0とした。
全周ではsourceにlog/codex/full_route_waypoint/fixedを使う。
fusion.jsonlは融合出力・品質判定、fusion.inputs.jsonlは同一走行の観測比較用データである。
fusion_review.json/pngは時刻を合わせた精度・経路横ずれ・適応baselineを示す。
評価コマンドは旧来のLIO単独精度基準も確認するため、goal_pass=trueでも終了コード1となり得る。

## 5. ビルド・テスト

通常とsymlinkの両方式でgnss_lio_fusion、obstacle_route_simをビルドし成功した。
対象パッケージ用の別build/installベースを使用し、既存生成物の削除は行っていない。
独自FAST-LIO/livoxは既存overlayを利用した旨のcolcon警告があり、新規ビルドしたという意味ではない。

```bash
colcon build --packages-select gnss_lio_fusion obstacle_route_sim
colcon build --symlink-install --packages-select gnss_lio_fusion obstacle_route_sim
pytest -q -p no:cacheprovider src/gnss_lio_fusion/tests src/obstacle_route_sim/tests src/robot_navigator/tests src/geo_pose_converter/tests
```

関連83件が成功した。新規パッケージの10件、模擬baseline変化の追加1件を含む。
実機ドライバの起動・実車走行は行っていない。

## 6. 評価の限界と次の改善

共分散は今回の実際の誤差を保証するものではなく、未校正の係数から算出した指標である。
不可能なLIOジャンプは除外するが、もっともらしい速度で蓄積する誤差を見抜けない場合がある。
LIO内部の点群照合残差・退化の監視と、車輪オドメトリによる相対運動の独立照合が必要である。
地図照合を追加する場合は、歪んだLIO地図をそのまま正解地図として使わない。
現段階で「融合すれば常にGPS単独より良い」「停止せず必ずコース内を完走する」とは判断しない。
実機の時刻同期、baseline分布、衛星数と誤差の関係、IMU雑音の校正が残る。

GUIや3D形式だけに依存せず、会話内にPNGと主要数値を掲載する。
PC内パスやlocalhostをiPhoneから到達可能なURLとして案内しない。

## 7. 融合制御による全周閉ループ結果

log/codex/fusion_trial/full_routeで、1,142 waypointを設定した全周を実行した。
第4章の全周sourceを使用し、baseline-shift=0.015、shift-after=0、timeout=7200とした。
conservative・seed=1、建物近傍GPS劣化、URG回避を有効にし、走行途中の推定器リセットや
手動介入は行っていない。以下は短区間や保存済み記録再生とは別の閉ループ試験である。

| 指標 | 結果 |
| --- | ---: |
| 終了状態 / goal_pass | FINISHED / true |
| 真値走行距離 | 2,226.93 m |
| 実時間 / LIO記録のシミュレーション時間 | 92.09分 / 65.95分 |
| 真値ゴール誤差 | 0.331 m |
| 車体中心の経路横ずれRMSE / P95 / 最大 | 0.710 / 1.330 / 3.761 m |
| 車体中心が元経路±1 m以内の比率 | 77.19% |
| 走行中の最長ほぼ静止時間（実時間） | 15.80秒 |
| 車体・支柱・アンテナへの接触イベント | 0 |
| 最終baseline推定値（設定515 mm） | 514.95 mm |

ほぼ静止は真値並進速度0.02 m/s未満かつyaw角速度0.05 rad/s未満とし、
最初のRUNNINGからFINISHEDまでを集計した。到着後の停止やその場旋回を含めない。
830番付近の回避では停滞し、既存route_managerが局所waypointを変更して復帰した。
route versionは100→101→102となった。通常のProceedログには830・833・834番が現れないが、
状態ログには各indexが存在する。この検査値は未訪問点数ではない。
最終index=1141へ到達した一方、元の全waypoint座標を変更せず通過したとは判断しない。
経路横ずれには回避による意図的な逸脱も含まれ、自己位置推定誤差とは区別する。

| 同一走行の自己位置誤差 | GPS観測 | LIO（初回XY/yaw整合） | 融合 |
| --- | ---: | ---: | ---: |
| XY RMSE | 1.329 m | 45.443 m | 1.669 m |
| XY誤差P95 | 2.383 m | 68.492 m | 2.231 m |
| 最大XY誤差 | 3.730 m | 72.923 m | 9.767 m |

共通19,045標本、除外734標本である。最大入力間隔はGPS 0.832秒、LIOと融合1.1秒だった。
全域の剛体合わせやICPで誤差を縮めてはいない。単独方式の閉ループ走行比較ではない。
融合はLIOの長期ドリフトを大きく抑制し、P95はGPS観測より小さくなったが、
RMSEと最大誤差はGPS観測より悪化した。長いFLOAT区間でLIOを優先するだけでは不十分である。
短区間だけを採用して融合全体を合格と判断しない。

診断出力はGPS_LIO 11,229、LIO_PRIORITY 12,848、LIO_FAULT 1標本であった。
最終累積はGPS採用34,465・棄却16,583、LIO異常ジャンプ棄却0、
時刻対応できなかったGPS 4,065、処理順序に対して遅れた入力0である。
同期不成立を除いた標本の精度だけで通信を含む全系の品質を保証しない。
起動した試験プロセスは終了処理で回収済みである。

評価器のresult.json内にある「SLAM・測位品質による切替は未検証」は旧GNSS評価用の
共通定型文であり、本試験の融合モード切替結果は上記診断とfusion_review.jsonを正とする。
同様にLIO単独の旧精度基準は不合格で、goal_passとは別判定である。
dropout_stop_pass=falseは本試験がdropout注入試験ではないため、停止性能の合否には用いない。

結論は「融合によるゴール到達を確認、無停止・経路±1 m維持は未達」とする。
車輪・キャスタの接触は監視対象外であり、接触ゼロでも実環境の安全性は証明しない。
航空写真等から構成し経路周辺を調整した地図での単一seed試験であり、
実測地形・歩行者・植生変動を網羅しない。baseline雑音と方位雑音の相関も再現していない。
実機校正、LIO内部の退化検出、車輪との整合判定、局所制御と大域補正のTF分離が残る。
